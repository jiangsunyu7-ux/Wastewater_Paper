# Stage3G pre-evaluation implementation review

This is a code/architecture review conducted before new target scores were computed. It does not establish forecasting or reliability benefit.

Reviewed new core primitives preserve Stage3B compact six-feature order, normalized missing placeholder 1 plus masks, positive-history-median scale with disclosed legacy 1 m³ fallback, origin-day/end-of-day retrospective Persistence, target-date-minus-seven weekly Persistence, and day-specific h=3. Four similarity descriptors use observed values only; change/autocorrelation require actual adjacent calendar pairs. Source descriptors aggregate same-budget annual histories ending 2016–2020, and each fold fits descriptor imputation/standardization on its current base sources only.

Weighted normal equations implement `sum_j w_j/n_j sum_t error² + alpha ||coef||²` with an unpenalized intercept. Positive source-total weights sum to one. This is weighted Ridge, not a new forecasting backbone or algorithmic first claim. Eta0 is the matched uniform method; lambda0 remains exact Persistence. A separate independent checker reconstructs saved forecasts and derives sufficient statistics directly from canonical rows rather than importing new scientific code.

The five source folds rotate disjoint outer-evaluation, risk-training and threshold-calibration roles; the remaining two folds fit the base model and provide inner source-only hyperparameter selection. Role registries must demonstrate held groups absent from base fitting, selection, descriptor standardization, risk fitting and threshold calibration. Final risk thresholds use source outer-cross-fitted risk scores rather than final-logistic fitted training scores. Risk parameters and threshold tie randomization are truth-independent at target deployment.

Two issues were raised before freezing: (1) selection uses an absolute normalized-MAE tolerance 1e-12 for ties, so wording must not claim exact numerical equality; (2) source risk predictions use source-only upstream alpha/lambda, so target shared methods should use the same source-only selection rule for all budgets. Target local methods can retain legitimate chronological internal validation. This changes matched Stage3G controls relative to historical Stage3C2 and must be disclosed. Root's final frozen protocol/config is authoritative; no old results are edited.

Remaining reliability-transfer limitations must be reported even after isolation checks pass: strict source risk bases use 12 groups versus the final target K30 model, and each outer logistic trains on six groups versus final logistic on 30. Cross-fitted score scale and event prevalence may change. Such source validation is not independent physical-facility or prospective deployment validation.

Current checks do not establish physical mapping or QA/data-arrival time. `physical_mapping_verified=false` and `verified_real_time=false`. All five target windows are used development history, and development labels never choose source settings, risk features or thresholds. Metadata gaps limit stronger claims but do not stop this explicitly authorized SiteID-level retrospective round.
